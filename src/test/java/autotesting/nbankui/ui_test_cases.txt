Примечания к кейсам

Условные обозначения
- ACC1, ACC2, ACC3 — условные имена счетов, созданных в предусловиях кейса.
Фактические номера присваивает система, они могут отличаться.
В шагах, сообщениях и списках подставляется фактический номер соответствующего счёта.
- "логин", пользователь A, пользователь B — условные обозначения пользователей, созданных в предусловиях.
- ACC999999 — пример номера счёта, которого нет в системе. Перед запуском убедиться, что такой номер не существует.

UI-DEP-01. Успешный депозит (параметризованный)
Предусловия (API)
1. Войти под администратором (admin / admin).
2. Создать пользователя с ролью USER.
3. Создать счёт пользователя (ACC1).
Предусловия (UI)
4. Открыть localhost:3000, войти под созданным пользователем.
Ожидается: открыта страница "User Dashboard", в шапке отображаются имя и логин.

Параметры
Сумма | Ожидаемое сообщение | Баланс ACC1 в списке счетов
100 | ✅ Successfully deposited $100 to account ACC1! | ACC1 (Balance: $100.00)
12.34 | ✅ Successfully deposited $12.34 to account ACC1! | ACC1 (Balance: $12.34)

Шаги и ожидаемые результаты
1. На дашборде нажать "Deposit Money".
Ожидается: открыта страница "Deposit Money", отображается форма с полями "Select Account" и "Enter Amount"
и кнопкой "Deposit". В списке есть -- Choose an account --, ACC1 (Balance: $0.00).
2. В "Select Account" выбрать ACC1 (Balance: $0.00).
Ожидается: в поле выбора отображается ACC1.
3. В поле "Enter Amount" ввести сумму из таблицы.
Ожидается: в поле отображается сумма из таблицы.
4. Нажать Deposit.
Ожидается: окно localhost:3000 says с сообщением из таблицы.
Ожидается: запрос deposit отправлен, статус 200.
5. Нажать OK.
Ожидается: окно закрыто, открыта страница "User Dashboard".
6. Перейти на страницу "Deposit Money", открыть список "Select Account".
Ожидается: баланс ACC1 из таблицы. Баланс показывается с двумя знаками после точки.

Постусловия: пользователь удаляется через API.

UI-NAME-02. Невалидное имя (параметризованный)
Предусловия (API)
1. Войти под администратором (admin / admin).
2. Создать пользователя с ролью USER.
3. Для строки со значением New Name: выставить пользователю имя New Name через API. Для остальных строк имя не задано.
Предусловия (UI)
4. Открыть localhost:3000, войти под созданным пользователем.
Ожидается: открыта страница "User Dashboard", в шапке отображается текущее имя из таблицы.

Параметры
Значение в поле | Текущее имя | Ожидаемое сообщение | Запрос на сервер
NewName | Noname | Name must contain two words with letters only | отправляется (ошибку возвращает сервер)
(пустое поле) | Noname | ❌ Please enter a valid name. | не отправляется
New Name | New Name | ⚠️ New name is the same as the current one. | не отправляется

Шаги и ожидаемые результаты
1. Нажать на блок с именем и логином в шапке (текущее имя @логин).
Ожидается: открыта страница "Edit Profile" с полем "Enter new name" и кнопкой "Save Changes". Поле пустое.
2. Ввести значение из таблицы (для пустого поля ничего не вводить).
Ожидается: в поле отображается введённое значение (для пустого поля поле пустое).
3. Нажать Save Changes.
Ожидается: окно localhost:3000 says с сообщением из таблицы.
Ожидается: сообщение "Name updated successfully!" не показывается.
Ожидается: наличие запроса на сервер совпадает со столбцом таблицы (проверка в Network).
4. Нажать OK.
Ожидается: окно закрыто, имя в шапке не изменилось.
5. Обновить страницу (F5).
Ожидается: в шапке то же имя, что и до шагов.

Постусловия: пользователь удаляется через API.

UI-TR-01. Успешный перевод (параметризованный)
Предусловия (API)
1. Войти под администратором (admin / admin).
2. Создать пользователя A (отправитель) и два его счёта: ACC1 и ACC2.
3. Внести на ACC1 пользователя A 1000. Баланс ACC2 остаётся 0.
4. Создать пользователя B (получатель) и один его счёт (ACC3).
Предусловия (UI)
5. Открыть localhost:3000, войти под пользователем A.
Ожидается: открыта страница "User Dashboard", в шапке отображаются имя и логин.

Параметры
Получатель | Сумма | Ожидаемое сообщение | ACC1 после перезагрузки | Баланс получателя
ACC3 (счёт пользователя B) | 100 | ✅ Successfully transferred $100 to account ACC3! | $900.00 | у пользователя B: ACC3 (Balance: $100.00)
ACC2 (свой счёт) | 100 | ✅ Successfully transferred $100 to account ACC2! | $900.00 | в списке пользователя A: ACC2 (Balance: $100.00)
ACC3 (счёт пользователя B) | 10.10 | ✅ Successfully transferred $10.10 to account ACC3! | $989.90 | у пользователя B: ACC3 (Balance: $10.10)

Шаги и ожидаемые результаты
1. Нажать "Make a Transfer".
Ожидается: открыта страница "Make a Transfer" с кнопками "New Transfer" и "Transfer Again",
полями "Select Your Account", "Recipient Name", "Recipient Account Number", "Amount",
чекбоксом "Confirm details are correct" (не отмечен) и кнопкой "Send Transfer".
2. Открыть список "Select Your Account".
Ожидается: в списке -- Choose an account --, ACC2 (Balance: $0.00), ACC1 (Balance: $1000.00). Других счетов нет.
3. Выбрать ACC1 (Balance: $1000.00).
Ожидается: в поле выбора отображается ACC1.
4. В "Recipient Account Number" ввести получателя из таблицы.
Ожидается: в поле отображается введённый номер счёта.
5. В "Amount" ввести сумму из таблицы.
Ожидается: в поле отображается сумма из таблицы.
6. Отметить чекбокс "Confirm details are correct".
Ожидается: чекбокс отмечен.
7. Нажать Send Transfer.
Ожидается: окно localhost:3000 says с сообщением из таблицы.
Ожидается: запрос transfer отправлен, статус 200.
8. Нажать OK.
Ожидается: окно закрыто, остаётся страница "Make a Transfer", поля формы очищены, чекбокс снят.
9. Обновить страницу (F5), открыть список "Select Your Account".
Ожидается: баланс ACC1 из таблицы. Баланс показывается с двумя знаками после точки.
10. Проверить баланс получателя: для ACC2 в списке пользователя A;
для ACC3 выйти, войти под пользователем B, открыть "Deposit Money" и список счетов.
Ожидается: баланс получателя из таблицы.

Постусловия: пользователи удаляются через API.

4. Создать пользователя B (получатель) и один его счёт (ACC3).
Предусловия (UI)
5. Открыть localhost:3000, войти под пользователем A.

Баланс ACC1 | Сумма | Ожидаемое сообщение
1000 | 1001 (больше баланса) | ❌ Error: Invalid transfer: insufficient funds or invalid accounts
1000 | 0 (корнер-кейс) | ❌ Error: Transfer amount must be at least 0.01
10010 | 10000.01 (больше лимита) | ❌ Error: Transfer amount cannot exceed 10000

Шаги и ожидаемые результаты

Ожидается: открыта страница "Make a Transfer" с кнопками "New Transfer" и "Transfer Again",

Ожидается: в поле выбора отображается ACC1.

Ожидается: поля заполнены, чекбокс отмечен.
5. Нажать Send Transfer.
Ожидается: окно localhost:3000 says с сообщением из таблицы.
Ожидается: запрос transfer отправлен, статус 400.
6. Нажать OK, обновить страницу (F5), открыть список "Select Your Account".

ПРИМЕЧАНИЯ К КЕЙСАМ

UI-DEP-01
- Вариант 12.34 проверяет отображение копеек.
- Поле суммы принимает больше двух знаков после точки (например, 1.0000000505050506),
окно показывает сумму без округления.

UI-DEP-03
- Некорректное поведение: при двойном клике уходит два запроса deposit со статусом 200,
появляются два окна "Successfully deposited $100 to account ACC1!" (после первого OK открывается второе),
в списке ACC1 (Balance: $200.00). Кнопка Deposit не блокируется на время обработки запроса.

UI-NAME-01
- Вопрос по поведению: на шаге 4 имя в шапке обновляется только после перезагрузки страницы.
Ожидание "без перезагрузки" построено на логическом представлении о работе приложения.

UI-NAME-02
- Сообщение для NewName показывается как есть из ответа сервера, без значка (в отличие от сообщений ❌ и ⚠️).
Замечание по единообразию сообщений.

UI-TR-01
- Ожидание на шаге 8 (остаётся страница "Make a Transfer", поля формы очищены, чекбокс снят)
построено на логическом представлении о работе приложения.
- Баланс в списке после OK не обновляется, он меняется только после перезагрузки страницы.
Ожидаемое поведение требует уточнения.
- Поле "Recipient Name" не обязательно, перевод проходит с пустым полем.
- Поле суммы принимает больше двух знаков после точки, окно показывает сумму без округления.

UI-TR-03
- В отличие от депозита, где 0 и лимит 5000 отсекаются на клиенте,
при переводе 0 и лимит 10000 проверяет сервер, поэтому запрос уходит.

UI-AUTH-01
- Некорректное поведение: для всех трёх адресов редиректа на "Login" нет, открывается пустая форма страницы (запросы данных возвращают 401).
  - /deposit: окно "Unauthorized! Please log in again." появляется дважды, затем открывается "Deposit Money" с пустым списком счетов.
  - /edit-profile: окно "❌ Failed to load profile.", затем пустая форма "Edit Profile".
  - /transfer: окно "❌ Unable to fetch transactions. Please try again.", затем пустая форма "Make a Transfer".
